# Pipetting Robot User Guide

This document is intended for normal day-to-day users of the pipetting robot software.

## 1. Purpose of the Software

The software helps you prepare and execute pipetting runs by:

1. defining the current robot hardware setup,
2. creating an Excel template for the experiment,
3. converting the filled Excel file into G-code,
4. supporting calibration of syringe-solvent combinations.

The software does not directly drive the robot during the run. It prepares the G-code that you later send to the machine with a host program such as Pronterface.

*Figure 1: Pronterface.*

## 2. What You Need Before Starting

Before using the software, make sure the following things are available:

1. the local database contains the syringe and solvents you want to use,
2. the selected syringe and each used solvent have a syringe-solvent link in the database,
3. the physical robot is assembled as described by the selected configuration,
4. a host program such as Pronterface is available for sending the final G-code to the machine.

Important:

1. Do not move, rename, or delete required application folders after installation.
2. Make sure the physical syringe matches the syringe selected in the software.
3. Make sure the racks on the robot match the saved rack definitions in the software.

## 3. Main Tabs of the GUI

The GUI is organized into four main tabs.

### 3.1 G-code

This is the main workflow tab. It is used to:

1. select the current setup, machine, syringe, and racks,
2. create an Excel template,
3. fill out the template,
4. generate the final G-code file.

You usually do not need to change the automatically generated G-code file path.

*Figure 2: PipetGui, G-code tab.*

### 3.2 Configuration

This tab is used to manage reusable configuration items:

1. setups,
2. machine definitions,
3. rack definitions.

*Figure 3: PipetGui, Configuration tab.*

### 3.3 Syringes and Solvents

This tab is used to maintain the database content:

1. syringes,
2. solvents,
3. syringe-solvent links.

*Figure 4: PipetGui, Syringes and Solvents tab.*

### 3.4 Calibration

This tab is used to:

1. generate calibration G-code,
2. evaluate measured calibration data,
3. update the calibration values stored for a syringe-solvent link.

*Figure 5: PipetGui, Calibration tab.*

## 4. The Normal Workflow in Short

For most users, the normal workflow is:

1. check that the correct syringe, solvent, and syringe-solvent links exist,
2. load or prepare the correct setup in the G-code tab,
3. create an Excel template,
4. fill in the Excel file,
5. generate G-code,
6. inside Pronterface, choose the COM port and connect,
7. load the generated G-code file in Pronterface,
8. make sure that the rack and machine configuration you use have valid coordinates and other definitions,
9. run the pipetting program in Pronterface using `Print`.

*Figure 6: From left to right: PipetGui icon, Excel file, G-code file, Pronterface. Workflow: choose the setup in PipetGui and create an Excel template, fill it out and generate the G-code file, connect to the robot via USB and Pronterface, load the generated G-code in Pronterface, and run it.*

## 5. Preparing the Database

Before a run, make sure the information in the `Syringes and Solvents` tab is correct. If you do not care about very high accuracy and only need roughly better than about 98 percent, you can sometimes use an already available solvent id with the current syringe, but the syringe-solvent link must still exist.

### 5.1 Syringes

Each syringe entry contains:

1. `id`: the internal database identifier,
2. `nominal volume, uL`: the maximum syringe volume,
3. `name`: the syringe name shown in the GUI,
4. `inner diameter, mm`: the inner diameter used to calculate the movement factor, meaning the plunger barrel inner diameter.

The `id` is used internally. The other values should match the real syringe you install on the robot.

*Figure 7: Syringes table.*

### 5.2 Solvents

Each solvent entry contains:

1. `id`: the internal database identifier,
2. `name`: the solvent name,
3. `density, g/ml`: the solvent density, important for gravimetric calibration,
4. `notes`: optional notes.

*Figure 8: Solvents table.*

### 5.3 Syringe-Solvent Links

Each syringe-solvent link stores calibration information for a solvent handled with one syringe.

Important fields:

1. `syringe id`: the syringe used,
2. `solvent id`: the solvent used,
3. `calibrated`: whether the link has been calibrated,
4. `backlash correction, mm`: the constant term of the linear calibration,
5. `real correlation factor, mm/uL`: the linear term of the calibration,
6. `since`: when the calibration was stored. The date format matters; time is autogenerated.

Important:

1. A solvent can only be used with a syringe if a matching syringe-solvent link exists.
2. If no precise calibration is available yet, the software can still store a theoretical starting factor. In practice, some users use acetone for organic solvents or water for water solutions if they seem hydrodynamically similar, but for the best precision you should calibrate the link later.

*Figure 9: Syringe solvent link table.*

## 6. Preparing the Configuration

The `Configuration` tab allows you to save reusable hardware definitions.

### 6.1 Setup

A setup combines:

1. one syringe,
2. one machine,
3. one ordered list of racks.

The rack order matters because it determines the global vial numbering and solvent numbering used later in the Excel file.

*Figure 10: Setup subtab inside the Configuration tab.*

### 6.2 Machine

The most important machine parameters are:

1. `z_min_limit`: the lowest allowed Z position for that machine,
2. `z_max_limit`: the highest allowed Z position for that machine,
3. `z_min`: the normal working Z level used when going down into racks,
4. `z_max`: the safe travel Z level used before XY movement,
5. `Fz`: the Z-axis feed rate,
6. `Fxy`: the XY-axis feed rate,
7. `Fa_push`: syringe feed rate during normal dispense,
8. `Fa_push_slow`: syringe feed rate during slow dispense,
9. `Fa_pull`: syringe feed rate during aspiration,
10. `rest_x` and `rest_y`: the parking position used at the end of a program.

*Figure 11: Machine subtab inside the Configuration tab.*

### 6.3 Rack

The most important rack parameters are:

1. `vial1_x` and `vial1_y`: position of the first vial,
2. `vial_dx` and `vial_dy`: spacing between vial positions,
3. `vial_rows` and `vial_columns`: vial grid dimensions,
4. `z_min_vials`: Z level used for vial access,
5. `solvent1_x` and `solvent1_y`: position of the first solvent slot,
6. `solvent_dx` and `solvent_dy`: spacing between solvent positions,
7. `solvent_rows` and `solvent_columns`: solvent grid dimensions,
8. `z_min_solvents`: Z level used for solvent access,
9. `waste_x` and `waste_y`: flush waste position for that rack.

If `z_min_vials` or `z_min_solvents` are left at the special default value in the GUI, the machine `z_min` is used instead.

*Figure 12: Rack subtab inside the Configuration tab.*

### 6.4 Save, Save As, and Add

The `Configuration` tab supports several useful actions:

1. `Add`: begin a new item,
2. `Save`: save changes to the selected item,
3. `Save As`: create a new item from the current form state,
4. `Rollback`: discard unsaved changes,
5. `Delete`: remove the selected item.

Typical use cases:

1. Use `Save` to update an existing configuration. If you change the name, the item configuration is renamed and setups inheriting it are updated as well.
2. Use `Save As` when you want to start from an existing machine, rack, or setup and create a new one with a different name. If the name field is not changed, `Save As` behaves like `Save`.

## 7. Preparing a Run in the G-code Tab

In the `G-code` tab, define what is currently mounted on the robot.

You have two options.

### 7.1 Select a Saved Setup

This is usually the fastest and safest approach.

1. Open the `Setup` dropdown.
2. Select a saved setup.
3. Check that the loaded syringe, machine, and racks match the actual robot.

### 7.2 Configure Manually

If no saved setup is appropriate:

1. choose the installed syringe,
2. choose the machine profile,
3. select the racks in the correct order.

Important:

1. The software currently works with one active syringe at a time.
2. The selected rack order affects the numbering used in the Excel template.

## 8. Creating the Excel Template

The software can create a ready-to-fill Excel workbook for the selected setup.

1. In the `G-code` tab, choose the output path for the template with `Save as...`.
2. Click `Create template`.
3. Open the saved `.xlsx` file.

The Excel program contains one solvent sheet and one vial sheet for each selected rack.

## 9. Understanding the Excel Program

This is the most important part for normal use.

### 9.1 Solvent Sheets

For every rack, the program contains a sheet named:

`<rack name>_solvents`

The rack name should not be longer than 16 symbols because of Excel constraints.

This sheet shows a colored solvent grid. Each cell represents one solvent position on the rack.

What to do on a solvent sheet:

1. hover over a colored cell to see the global solvent index in the comment,
2. type the solvent id into the cell from the `Syringes and Solvents` tab in PipetGui,
3. repeat for every solvent position you want to use.

Important distinction:

1. `solvent id` is the database id of the solvent in the `Syringes and Solvents` tab,
2. `solvent index` is the position number used inside the Excel program.

These are not the same thing.

Example:

1. You may place solvent id `7` into solvent position `1`.
2. Later, in a vial program, you refer to that position by `solvent index = 1`, not by solvent id `7`.

Notes:

1. If a solvent cell is left empty, that solvent position is treated as unassigned.
2. If a vial program refers to a solvent index whose solvent cell is empty, G-code generation fails.
3. The solvent id must exist in the database.
4. The selected syringe must have a syringe-solvent link for that solvent.

### 9.2 Vial Sheets

For every rack, the workbook contains a sheet named:

`<rack name>_vials`

This sheet has two parts:

1. a top vial grid showing the global vial indices for visual convenience,
2. a program table below it.

The vial index column in the program table tells you which table row belongs to which vial.

### 9.3 What a Stage Means

The program table is organized in stages.

A stage is one group of columns:

1. `volume uL`,
2. `solvent index`,
3. optionally `flush`.

You can add more stages by copying the existing stage columns to the right.

Important:

1. The software executes the program stage by stage.
2. This means it processes stage 1 over all vials first, then stage 2 over all vials, then stage 3 over all vials, and so on.
3. It does not finish one vial completely before moving to the next vial. It only proceeds stage by stage.

### 9.4 How to Fill a Normal Stage

For each vial row:

1. enter the volume in `uL`,
2. enter the solvent index,
3. optionally define a flush behavior.

If a whole stage row for a vial is left empty, that stage is skipped for that vial.

### 9.5 Flush Behavior

The `flush` column is optional.

Accepted values are:

1. empty: no flush,
2. `FALSE` or `0`: no flush,
3. `TRUE`: flush with the same solvent used for that dispensing step,
4. an integer solvent index: flush with the solvent located at that global solvent index.

Advanced note:

1. A row can also be used for a flush-only operation.
2. For a flush-only row, input the integer solvent index in the flush column and leave the solvent index and volume columns empty.

### 9.6 Slow Dispense

If you fill a volume cell with any background color in Excel, the software interprets that dispense as a slow dispense.

Set the fill back to `No Fill` if you want to switch back to the normal dispense speed.

This can be useful, for example, when:

1. the liquid should be added more gently,
2. crystallization or precipitation behavior makes a slower dispense desirable.

### 9.7 Large Volumes

If a requested volume is larger than the syringe capacity, the software can split it internally into several smaller transfers.

Even so, it is still good practice to choose a syringe size that is sensible for the planned volumes.

### 9.8 Common Excel Mistakes

The most common mistakes are:

1. confusing solvent id and solvent index,
2. forgetting to assign a solvent id on the solvent sheet,
3. using a solvent id that does not exist in the database,
4. using a syringe-solvent pair that has no link in the database,
5. forgetting to save the Excel file before generating G-code,
6. filling a stage header incorrectly after copying columns. Do not change the header names.

## 10. Generating G-code

Once the Excel program is ready:

1. return to the `G-code` tab inside PipetGui,
2. select the completed Excel file path if it was not automatically selected,
3. select the output path for the `.gcode` file if it was not automatically selected,
4. click `Generate G-code`.

If generation succeeds, the program writes the output G-code file and reports success in the log.

If generation fails, read the log message carefully. Most failures come from:

1. missing or invalid solvent assignments,
2. invalid solvent indices,
3. empty required cells,
4. missing syringe-solvent links,
5. invalid setup data.

## 11. Running the Robot

The generated G-code is normally run through a host program such as Pronterface.

Recommended workflow:

1. connect to the robot via USB,
2. home the robot,
3. if you want to manually verify important positions at low speed, drive the robot only at the highest safe Z coordinate,
4. open the generated `.gcode` file using `Load File`,
5. start the run using `Print`,
6. closely supervise the first run of every new configuration or new protocol.

To drive the robot manually in Pronterface, write commands in the console below, for example:

1. `G1 X<> Y<>`
2. `G1 Z<>`

Check the desired machine configuration inside PipetGui for `z_max` and `z_min` before doing manual moves.

Recommended manual position checks in Pronterface after homing:

1. horizontal test move: `G1 X<mm> Y<mm> F1000`
2. vertical test move: `G1 Z<mm> F300`

Replace `<mm>` with safe test coordinates.

Important:

1. Always move carefully when testing a new rack or machine configuration.
2. Keep an emergency stop or power cutoff accessible.

## 12. Calibration Guide

Calibration is mainly needed when high precision is required.

### 12.1 What Calibration Changes

Calibration updates the syringe-solvent link values:

1. `CF` or correlation factor: the linear term,
2. `BC` or backlash correction: the constant term.

These values define how the software converts requested liquid volume into the syringe plunger movement.

### 12.2 When Calibration Is Usually Needed

This is mostly a superuser task.

Typical cases:

1. a new syringe is introduced,
2. a new solvent is introduced,
3. accuracy over 99 percent is critical,
4. dispensing behavior has changed. In that case, please report it to the superuser.

### 12.3 Recommended Calibration Settings

Good practical defaults are:

1. `7` datapoints,
2. `3` repeats per datapoint,
3. start at 10 percent of syringe volume,
4. end at 100 percent of syringe volume.

In many cases, 3-5 datapoints are already enough.

Two consecutive calibration runs are usually sufficient. For water, the first run is often already above 99.95 percent accuracy, and the second run mainly helps quantify the remaining error.

### 12.4 Same Vial Calibration

This is usually the preferred method.

Use it when:

1. you want a faster workflow,
2. you have the scale with the vial-tower setup,
3. you do not use a septum.

Advantages:

1. faster,
2. more convenient,
3. the measured mass can be entered during the run.

You can also define a pause duration in the calibration tab for this workflow.

### 12.5 Different Vials Calibration

This method is slower, but it can still be useful.

Possible use cases:

1. calibration of the 10 uL syringe in contact mode,
2. calibration of vials with a septum, using the black lid with openings so that the syringe does not drag the vials.

### 12.6 Calibration Evaluation

After choosing syringe and solvent in the `Calibration` tab:

1. the current solvent name is shown,
2. the current `CF` and `BC` values are shown,
3. the evaluation table displays expected masses for the ideal case as placeholder values.

You can enter measured masses in grams.

The software also accepts subtraction input such as:

`0.3480-0.2070`

This is useful when you measure difference masses from a balance.

After clicking `Evaluate calibration`, even if you do not want to apply the calibration yet, the software calculates:

1. the mean absolute percentage error,
2. the updated `CF`,
3. the updated `BC`.

After clicking `Apply calibration`, the software writes the new values directly into the syringe-solvent link in the database.

## 13. Troubleshooting

### 13.1 The Program Cannot Find My Solvent

Check:

1. the solvent exists in the solvent table,
2. the correct solvent id was entered into the solvent sheet,
3. the selected syringe has a syringe-solvent link for that solvent.

### 13.2 The Program Reports an Invalid Solvent Index

Check:

1. the solvent index in the vial sheet refers to a real solvent position,
2. the corresponding solvent cell on a solvent sheet is filled,
3. the rack order in the setup is correct.

### 13.3 G-code Generation Fails Even Though the Excel File Looks Fine

Check:

1. that the Excel file was saved,
2. that copied stage columns still have correct headers,
3. that required cells are not empty,
4. that the selected setup really matches the workbook you created.

### 13.4 The Robot Moves to the Wrong Place

Check:

1. the machine configuration,
2. the rack configuration,
3. the physical placement of the racks,
4. the rack order in the selected setup.

Do a low-speed manual position test before running a new configuration.

## 14. Good Daily Practice

Recommended habits for reliable operation:

1. use saved setups whenever possible,
2. keep syringe, solvent, and link data tidy,
3. use meaningful names for configurations,
4. save the Excel file before every G-code generation,
5. verify positions after any hardware change,
6. supervise the first run of every new method,
7. recalibrate when accuracy over 99 percent becomes important.
